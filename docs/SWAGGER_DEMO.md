# Руководство по Swagger UI — Retro-Streamer

## 1. Назначение

Swagger UI предоставляет интерактивную документацию REST API проекта Retro-Streamer. С его помощью можно изучать методы API, проверять схемы запросов и ответов, выполнять запросы и проверять требования к авторизации.

После запуска приложения интерфейс доступен по адресу:

`http://localhost:8000/docs`

Альтернативная документация ReDoc:

`http://localhost:8000/redoc`

Все REST-эндпоинты проекта используют префикс `/api/v1`.

## 2. Основные группы API

| Группа | Назначение |
|---|---|
| `auth` | Регистрация, вход, обновление токенов и выход |
| `game` | Получение информации об игре, запуск рендеринга и скачивание результатов |
| `game_ws` | Получение обновлений о выполнении задачи через WebSocket |
| `leaderboard` | Получение результатов и таблицы лидеров |

Названия групп в интерфейсе зависят от `tags`, указанных в исходном коде FastAPI.

## 3. Авторизация

### Регистрация

Метод: `POST /api/v1/auth/register`

1. Откройте метод в Swagger.
2. Нажмите **Try it out**.
3. Заполните поля согласно отображаемой схеме запроса.
4. Нажмите **Execute**.
5. Проверьте HTTP-статус и тело ответа.

### Вход

Метод: `POST /api/v1/auth/login`

Выполните запрос с данными тестового пользователя. Сохраните `access_token`, если он присутствует в ответе.

Для защищённых методов используйте кнопку **Authorize**, если Bearer Authentication настроена в OpenAPI.

Формат заголовка:

`Authorization: Bearer <access_token>`

Refresh-токен передаётся через cookie. Его обновление и удаление зависят от реализации механизмов сессии.

Не публикуйте реальные токены, пароли или содержимое cookie в скриншотах и видеозаписях.

## 4. Получение информации об игре

Метод:

`GET /api/v1/game/info/{game_name}?seed={seed}`

Пример для Snake:

`GET /api/v1/game/info/snake?seed=42`

Поддерживаемые названия игр: `snake`, `2048`, `labyrinth`, `sokoban`.

Параметр `seed` задаёт начальные условия игрового сценария, если реализация конкретной игры использует его для воспроизводимой инициализации.

В ответе изучите структуру начального состояния и описание игры.

## 5. Запуск генерации GIF

Метод:

`POST /api/v1/game/render`

Этот метод запускает обработку в фоне. Сам рендеринг выполняется Celery worker, поэтому HTTP-запрос не обязан ждать завершения всей генерации.

Порядок действий:

1. Откройте метод в Swagger.
2. Нажмите **Try it out**.
3. Изучите схему `RenderRequest`.
4. Заполните тело запроса в соответствии с обязательными полями и ограничениями.
5. Нажмите **Execute**.
6. Сохраните идентификатор задачи из ответа.

Не используйте произвольное JSON-тело: корректные поля и варианты игрового запроса определяются реальными схемами приложения.

## 6. Отслеживание статуса задачи

Метод:

`GET /api/v1/game/tasks/{task_id}`

Подставьте идентификатор, полученный при создании задачи.

Повторяйте запрос, чтобы увидеть изменение статуса. Конкретные названия статусов и формат ответа следует сверить с фактической схемой ответа проекта.

Этот этап демонстрирует разделение между приёмом запроса и выполнением длительной фоновой операции.

## 7. Обновления через WebSocket

Endpoint:

`/api/v1/game/stream/{task_id}?token={access_token}`

WebSocket предназначен для получения обновлений о выполнении задачи без постоянного повторения REST-запросов.

Для демонстрации можно использовать отдельный WebSocket-клиент. Передавайте действительный токен тестового пользователя и идентификатор существующей задачи.

Учитывайте, что передача токена в query string может привести к его попаданию в журналы прокси или сервера. Для production необходимо пересмотреть этот способ аутентификации и настроить маскирование чувствительных данных в логах.

## 8. Скачивание готового результата

Метод:

`GET /api/v1/game/download/{render_id}`

После успешного завершения задачи используйте идентификатор сохранённого рендера.

Endpoint возвращает перенаправление на ссылку для получения файла. В зависимости от конфигурации MinIO/S3 браузер может начать скачивание или открыть другой URL.

Для production необходимо проверить срок жизни подписанной ссылки, приватность бакета и права пользователя на доступ к конкретному рендеру.

## 9. Таблица лидеров

Метод:

`GET /api/v1/leaderboard/{game_name}`

Пример пути:

`GET /api/v1/leaderboard/snake`

Поддерживаются параметры фильтрации:

| Параметр | Назначение |
|---|---|
| `season_id` | Идентификатор сезона |
| `seed` | Фильтрация по seed |
| `limit` | Количество результатов, от 1 до 100; значение по умолчанию — 20 |
| `offset` | Смещение при пагинации; значение по умолчанию — 0 |

Проверьте в Swagger, какие параметры обязательны для конкретного метода, и используйте существующие записи в базе.
